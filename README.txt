ตารางกิจวัตรประจำสัปดาห์ — แพ็กเกจติดตั้งใช้งานออฟไลน์
========================================================

ไฟล์ในแพ็กเกจนี้
- index.html          หน้าตารางหลัก (เปิดไฟล์นี้เพื่อใช้งาน)
- manifest.json        ข้อมูลแอปสำหรับ "ติดตั้งเป็นไอคอน"
- service-worker.js     ทำให้เปิดใช้งานได้แม้ไม่มีอินเทอร์เน็ต หลังเปิดครั้งแรก
- assets/icon-192.png   ไอคอนแอป ขนาดเล็ก
- assets/icon-512.png   ไอคอนแอป ขนาดใหญ่

วิธีติดตั้งเป็นไอคอนบนมือถือ (Android / Chrome)
1. แตกไฟล์ zip นี้เก็บไว้ในเครื่อง (โฟลเดอร์ไหนก็ได้ เช่น ในมือถือหรือใน Google Drive)
2. เปิดไฟล์ index.html ด้วย Chrome
   - ถ้าเก็บในมือถือ: ใช้แอปจัดการไฟล์เปิดด้วย Chrome ได้เลย
   - ถ้าอยากได้ลิงก์ถาวรกดจากที่ไหนก็ได้: อัปโหลดทั้งโฟลเดอร์ขึ้น Google Drive แล้วเปิดผ่านเว็บ หรือใช้บริการโฮสต์ไฟล์ฟรี เช่น GitHub Pages / Netlify Drop (ลากทั้งโฟลเดอร์วางแล้วได้ลิงก์ทันที)
3. กดเมนู ⋮ (มุมขวาบน) เลือก "เพิ่มไปยังหน้าจอหลัก" (Add to Home screen)
4. จะได้ไอคอนปฏิทินสีอุ่น ๆ ไว้ที่หน้าจอโฮม กดเปิดได้เหมือนแอปทั่วไป ไม่มีแถบ URL ของเบราว์เซอร์

วิธีติดตั้งบน iPhone (Safari)
1. ทำตามข้อ 1-2 ด้านบน แต่เปิดไฟล์ด้วย Safari แทน Chrome
2. กดปุ่มแชร์ (สี่เหลี่ยมมีลูกศรชี้ขึ้น)
3. เลือก "เพิ่มไปยังหน้าจอโฮม" (Add to Home Screen)

วิธีใช้บนคอมพิวเตอร์
- ดับเบิลคลิก index.html เปิดด้วยเบราว์เซอร์ได้เลย ไม่ต้องเชื่อมต่ออินเทอร์เน็ต
- ปักหมุด (bookmark) ไว้ในเบราว์เซอร์เพื่อเปิดซ้ำได้เร็ว

หมายเหตุ
- การ "ติดตั้งเป็นไอคอนจริง ๆ" (Add to Home Screen) ต้องเปิดไฟล์ผ่าน URL ที่ขึ้นต้นด้วย http:// หรือ https:// เท่านั้น
  (เบราว์เซอร์บางตัวไม่อนุญาตให้ติดตั้งจากไฟล์ในเครื่องโดยตรง file://)
  ถ้าเจอปัญหานี้ ให้อัปโหลดทั้งโฟลเดอร์ขึ้นที่เก็บไฟล์ออนไลน์ฟรีก่อน เช่น
  - Netlify Drop: https://app.netlify.com/drop (ลากทั้งโฟลเดอร์วาง ไม่ต้องสมัครสมาชิก)
  - GitHub Pages
  แล้วเปิดลิงก์ที่ได้ด้วยเบราว์เซอร์มือถือ จากนั้นค่อยกด "เพิ่มไปยังหน้าจอหลัก"
- ข้อมูลทั้งหมดในตารางฝังอยู่ในไฟล์ index.html ไม่ต้องเชื่อมต่ออินเทอร์เน็ตเพื่อดูข้อมูล


========================================================
เพิ่มใหม่: เครื่องเล่นเพลงออฟไลน์ (Offline Music Player)
========================================================
ตัวเว็บ/ตารางเดิมไม่เปลี่ยน ส่วนเพลงถูกเพิ่มเป็นบล็อกแยกใน index.html
(CSS + HTML + JavaScript ท้ายไฟล์) และ service-worker.js เปลี่ยนเฉพาะชื่อ cache เป็น v2
เพื่อให้เครื่องที่เคยติดตั้งไว้ได้รับ index.html ฉบับใหม่

วิธีติดตั้ง/เปิดเป็น PWA
- เหมือนเดิมทุกประการ (ดูหัวข้อ "วิธีติดตั้งเป็นไอคอนบนมือถือ" ด้านบน)
- หากเคยติดตั้งไว้แล้ว ให้เปิดแอปตอนออนไลน์ 1 ครั้งเพื่อให้ได้เวอร์ชันใหม่

วิธีเพิ่มเพลง
1. แตะแถบเพลงด้านล่างจอเพื่อเปิดเครื่องเล่น
2. แตะ "เพิ่มเพลง" (ในหน้าว่าง หรือในรายการเพลง) แล้วเลือกไฟล์เสียงจากเครื่อง เลือกได้หลายไฟล์
3. ไฟล์ที่เพิ่มสำเร็จจะถูกเก็บในเครื่อง และเพลงแรกที่เพิ่มจะเริ่มเล่นให้
   - รองรับเฉพาะไฟล์เสียงที่เบราว์เซอร์เล่นได้ (เช่น mp3, m4a, aac, wav, ogg/opus, flac)
   - mp3 ที่มีแท็ก ID3 จะอ่านชื่อเพลง ศิลปิน และรูปปกให้อัตโนมัติ ถ้าไม่มีจะใช้ชื่อไฟล์
   - ไฟล์ชื่อและขนาดเดียวกันที่มีอยู่แล้วจะถูกข้าม

วิธีลบเพลง
- เปิดรายการเพลง แล้วแตะไอคอนถังขยะท้ายแถวของเพลงนั้น → ยืนยัน
- การลบจะลบทั้งข้อมูลเพลงและไฟล์เสียงออกจากที่เก็บในเครื่องจริง ๆ (ไม่ใช่แค่ซ่อน)

วิธีใช้งานแบบ Offline
- เพลงที่เพิ่มแล้วเก็บอยู่ในเครื่อง ปิด/เปิดแอปใหม่หรือไม่มีอินเทอร์เน็ตก็ยังเล่นได้
- ตัวเว็บเปิดแบบออฟไลน์ได้ผ่าน service worker เหมือนเดิม (service worker ไม่ได้แคชไฟล์เพลง)
- Shuffle เป็นเพียงโหมดการเล่น ไม่เปลี่ยนลำดับเพลงในรายการ
- Repeat สลับได้ 3 แบบ: ทั้งรายการ / เพลงนี้ / ปิด
- บน iPhone/iPad ระบบไม่ยอมให้เว็บปรับระดับเสียง จะเหลือเฉพาะปุ่มปิดเสียง

ข้อจำกัดเรื่อง Autoplay
- เบราว์เซอร์ไม่อนุญาตให้เว็บเริ่มเสียงเองโดยไม่มีการแตะ/กดจากผู้ใช้ เว็บนี้ไม่พยายามหลีกเลี่ยงกฎนี้
- เมื่อเปิดแอปใหม่ จะโหลดเพลงล่าสุดรอไว้ แล้วต้องกด ▶ เองหนึ่งครั้ง
- หลังเริ่มเล่นแล้ว เพลงถัดไปจะเล่นต่ออัตโนมัติตามโหมด repeat/shuffle
- บางเบราว์เซอร์ (เช่น Safari) อาจไม่เล่นเพลงที่เพิ่งเพิ่มให้ทันที ให้กด ▶ ได้เลย

โครงสร้างการเก็บข้อมูลโดยสรุป
- IndexedDB ชื่อ "weekly-music" (เวอร์ชัน 1) มี 3 store
  - tracks : id, title, artist, fileName, mime, size, createdAt, duration, thumb (รูปย่อ),
             hasCover, sourceType ("local"; เผื่อขยายเป็น "url-import" ภายหลัง), sourceRef
  - blobs  : { id, blob } ไฟล์เสียงจริง
  - covers : { id, blob } รูปปกขนาดย่อ (ถ้ามี)
- localStorage คีย์ "weeklyMusic.settings" เก็บเฉพาะค่าเล็ก ๆ: volume, muted, shuffle, repeat, lastId
- เว็บขอ persistent storage หลังเพิ่มเพลงครั้งแรก (ถ้าเบราว์เซอร์รองรับ) และแจ้งเตือนเมื่อพื้นที่ไม่พอ
- หากล้างข้อมูลเว็บไซต์ในเบราว์เซอร์ เพลงที่เพิ่มไว้จะหายไปด้วย

เวอร์ชัน Daily Dashboard (ฉบับล่าสุด) — สิ่งที่เพิ่ม/เปลี่ยน
========================================================
ข้อมูลตาราง (days / goals / rules / principles) ไม่ถูกแก้ ฟังก์ชันเดิมทั้งหมดยังอยู่

1) นาฬิกา real-time (ภาษาไทย): วัน วันที่ เดือน ปี (พ.ศ./ค.ศ.) ชม:นาที:วินาที สลับ 24/12 ชม. ได้ (จำค่าไว้)
   - อัปเดตทุกวินาทีโดยยิงที่ขอบวินาที อ่านจาก Date ของเครื่องทุกครั้ง จึงไม่ drift
   - หยุดทำงานตอนแท็บถูกซ่อน และ sync ใหม่ทันทีเมื่อกลับมา (ไม่ใช้ setInterval 1ms)
2) เปิดเว็บแล้วเลือกวันปัจจุบันให้อัตโนมัติ และเปลี่ยนวันเองเมื่อข้ามเที่ยงคืน
   - ถ้าผู้ใช้กดดูวันอื่นเอง ระบบจะไม่ดึงกลับ มีแถบ "กลับไปวันนี้"
   - กิจกรรมปัจจุบันคำนวณจากวัน/เวลาจริงเท่านั้น ไม่เกี่ยวกับวันที่กำลังเปิดดู
3) การ์ด "กำลังทำอยู่ตอนนี้" (ชื่อ เวลา progress เวลาที่เหลือ) + "กิจกรรมถัดไป" (นับถอยหลัง)
   - ใช้กฎ start <= now < end ; รายการเวลาเดียว (เช่น 22:00 นอน) ถือเป็นกิจกรรมที่เริ่มตอนนั้นจนสิ้นวัน
   - ช่วงที่ไม่มีกิจกรรมจะแสดง "ยังไม่มีกิจกรรมในช่วงเวลานี้" พร้อมกิจกรรมถัดไป
   - แถวปัจจุบันในตารางถูกไฮไลต์ ; DOM อัปเดตเฉพาะตอนกิจกรรมเปลี่ยน (progress/เวลาที่เหลืออัปเดตเฉพาะข้อความ)
   - ฟังก์ชันหลักใน index.html: parseTimeRange(), timeToMinutes(), getCurrentActivity(), getNextActivity()
4) เครื่องเล่นเพลง: จำเพลงล่าสุด + ตำแหน่ง (lastId, lastPosition, lastUpdated, wasPlaying) ใน localStorage
   - บันทึกเมื่อ pause/seek/visibilitychange/pagehide/beforeunload และทุก ~4 วินาทีระหว่างเล่น
   - เปิดใหม่: โหลดเพลง รอ loadedmetadata แล้วคืนตำแหน่ง (ถ้าเกิน duration → 0) แล้วพยายามเล่นต่อ
     ถ้าเบราว์เซอร์บล็อก autoplay (ไม่มีการ bypass) จะขึ้น "พร้อมเล่นต่อจาก m:ss • แตะ ▶"
   - เพลงที่ lastId ชี้ถูกลบ → ล้าง state แล้วใช้เพลงอื่น ; ไฟล์เสียงยังอยู่ใน IndexedDB เหมือนเดิม
5) เลย์เอาต์มือถือ: ตารางเป็นการ์ดแนวตั้งที่ ≤600px (ไม่มี scroll แนวนอน), ปุ่ม ≥44px,
   เผื่อพื้นที่ใต้หน้าตามความสูงจริงของ mini player + safe area
6) service-worker.js เป็น cache v3 : หน้า HTML ใช้ network-first (ได้ไฟล์ใหม่เสมอเมื่อออนไลน์) fallback แคชเมื่อออฟไลน์
   ไม่แตะ IndexedDB จึงไม่ทำให้เพลงหาย (เปิดแอปออนไลน์ 1 ครั้งเพื่อรับเวอร์ชันใหม่)

เพิ่มใหม่: Checklist + แจ้งเตือนก่อนเปลี่ยนกิจกรรม + เสียงแจ้งเตือน MP3 (cache v4)
========================================================
ตารางกิจกรรม เป้าหมาย กฎ สี นาฬิกา เครื่องเล่นเพลง และ IndexedDB "weekly-music" ไม่ถูกเปลี่ยน
ส่วนใหม่เพิ่มเป็นบล็อก CSS/HTML/JS แยก (ท้ายไฟล์ index.html) และ service-worker.js เปลี่ยนเป็น v4

วิธีใช้
- Checklist: แต่ละกิจกรรมมีปุ่ม ✓ ทำแล้ว / — ไม่ได้ทำ (ข้ามเลย) / ! ไม่ผ่าน (ลองทำแล้วแต่ไม่ถึงเกณฑ์)
  แตะปุ่มเดิมซ้ำ = กลับเป็น ○ ยังไม่ได้เช็ก กิจกรรมปัจจุบันมีปุ่มเดียวกันในการ์ด "กำลังทำอยู่ตอนนี้"
- สรุปผลของวันอยู่เหนือตาราง + ปุ่ม "รีเซ็ตสถานะวันนี้" (มียืนยัน และกด "เลิกทำ" ได้) ล้างเฉพาะวันนี้
- วันที่ยังไม่ถึง (เช่น ดูตารางพรุ่งนี้) ดูได้แต่ยังบันทึกสถานะไม่ได้
- แจ้งเตือน: ปุ่ม "แจ้งเตือน" ใต้วันที่ → เปิดสวิตช์ (ระบบขอสิทธิ์เฉพาะตอนผู้ใช้กดเปิด)
  เตือนก่อนจบกิจกรรม: อัตโนมัติ (≥30 นาที = 10 นาที, 10–29 นาที = 5 นาที, สั้นกว่านั้นไม่เตือน) หรือกำหนด 5/10 นาที
- เสียงแจ้งเตือน: ค่าเริ่มต้นสร้างจากโค้ด หรือเลือก MP3 (ไม่เกิน 8 MB) มี ▶ ทดลองเสียง / เปลี่ยนไฟล์ / คืนค่าเริ่มต้น

โครงสร้างข้อมูล (ทั้งหมดอยู่ในเครื่อง ไม่มี backend/tracking)
- localStorage "weekly.checklist.v1"  {days:{"2026-10-01":{"thu@13:00":"d|s|f"}}}  → แยกตามวันที่จริง วันจันทร์ใหม่เริ่มว่าง
  (รหัสกิจกรรม = วัน@เวลาเริ่ม จึงไม่ผูกกับลำดับแถว; ไม่เก็บ "ยังไม่ได้เช็ก" เพื่อประหยัดที่)
- localStorage "weekly.notify.settings" / "weekly.notify.fired" (กันเตือนซ้ำ: วันที่ + กิจกรรม + ชนิด เก็บ 7 วัน)
- IndexedDB ฐานใหม่ "weekly-notify" (store "sounds") แยกจาก "weekly-music" จึงไม่ต้อง migrate และไม่กระทบเพลง

จุดที่จำเป็นต้องแก้ของเดิม (แก้เฉพาะจุด)
1) Daily Dashboard tick(): เพิ่มการจำ "วันที่จริง" (todayKey) ตรวจข้ามวันด้วยวันที่ ไม่ใช่แค่ชื่อวัน
   (เดิมถ้าเปิดค้างข้ามสัปดาห์ จันทร์→จันทร์ จะไม่ถูกมองว่าเปลี่ยนวัน) และส่งชีพจรไปให้ Checklist/Notification
   แทนการสร้าง loop ใหม่ → ไม่มี timer ต่อกิจกรรม มีตัวปลุกเดียวสำหรับตอนแอปอยู่เบื้องหลัง
2) selectDay(): แจ้ง Checklist เมื่อเปลี่ยนวันที่ดู
3) Music Player: เพิ่ม window.__music (playing/duck/unduck/resume) เพื่อให้เสียงแจ้งเตือน "ลดเสียงเพลงชั่วคราว"
   โดยไม่หยุด/ไม่ reset เพลง และไม่แตะค่าที่บันทึก (lastId/lastPosition/wasPlaying ฯลฯ)
4) service-worker.js: cache v3 → v4 และเพิ่ม notificationclick (แตะการแจ้งเตือนแล้วเปิดแอป)

ข้อจำกัดของแพลตฟอร์ม (ไม่มีวิธีเลี่ยงที่ปลอดภัยโดยไม่มีเซิร์ฟเวอร์)
- เว็บที่ไม่มี push server ไม่สามารถ "ปลุก" แอปที่ถูกปิด/ถูกระงับได้ การแจ้งเตือนจึงทำงานเมื่อแอปเปิดอยู่ (แบนเนอร์ + เสียง)
  หรืออยู่เบื้องหลังแต่ยังไม่ถูกระงับ (การแจ้งเตือนของระบบ) ถ้าเบราว์เซอร์ระงับแอป การเตือนที่พลาดจะแสดงเป็นแบนเนอร์
  ตอนกลับมาเปิดแอป ถ้ากิจกรรมนั้นยังไม่จบ
- เสียง MP3 ที่เลือกเล่นได้ตอนเปิดแอปอยู่ ส่วนการแจ้งเตือนของระบบใช้เสียงของเครื่อง (เบราว์เซอร์ไม่ให้กำหนดเสียงเอง)
- iPhone: การแจ้งเตือนของระบบใช้ได้เมื่อ "เพิ่มไปยังหน้าจอโฮม" แล้วเท่านั้น (iOS 16.4+)
- เบราว์เซอร์มือถือต้องมีการแตะหน้าจออย่างน้อย 1 ครั้งก่อน จึงจะเล่นเสียงแจ้งเตือนอัตโนมัติได้

เพิ่มใหม่ (รอบ 2): สรุปสัปดาห์ + ธีม + ปกเพลงที่ตั้งเอง (cache v5)
========================================================
สิ่งที่ "ยังไม่ได้ทำ" ในรอบนี้ (ตั้งใจ ไม่อ้างว่าทำ): AI วิเคราะห์ / AI Chat / Adaptive Schedule / Schedule Versioning
  เพราะต้องมี backend หรือ proxy เก็บ API key (ห้ามฝังใน frontend) และต้องมีโมเดลข้อมูล "ตารางแก้ไขได้" ซึ่งตารางปัจจุบันเป็นค่าคงที่ในโค้ด
  สรุปสัปดาห์ในรอบนี้คำนวณในเครื่อง ไม่ส่งข้อมูลออกนอกเครื่อง และไม่ใช่ AI

1) สรุปสัปดาห์ (ปุ่ม "📊 สรุปสัปดาห์" ใต้สรุปผลของวัน)
- ตัดรอบ จันทร์–อาทิตย์ ตามเวลาท้องถิ่นของเครื่อง ดูย้อนหลังได้ 12 สัปดาห์
- สัปดาห์ที่จบแล้วและมีการเช็กอย่างน้อย 1 รายการ จะเก็บ snapshot (localStorage "weekly.summary.v1") ผลย้อนหลังจึงไม่เปลี่ยนเองถ้าแก้ข้อมูลดิบภายหลัง
- แยก 3 ส่วนชัดเจน: ข้อเท็จจริง / ข้อสังเกต (การตีความ) / แนวทางที่ลองได้
- นับ "ไม่ได้ทำ" กับ "ไม่ผ่าน" แยกกัน และไม่ถือว่า "ยังไม่ได้เช็ก" = ล้มเหลว
- ข้อมูลที่เช็กแล้วน้อยกว่า 10 รายการ → แสดง "ข้อมูลยังไม่เพียงพอ" และไม่สร้าง pattern; ข้อมูลน้อยกว่า 3 สัปดาห์ → บอกว่าเป็นภาพรวมเบื้องต้น
- ไม่แนะนำให้ตัดเวลาพัก/อาหาร/เผื่อเวลาเพื่อเพิ่มผลงาน

2) ธีม (ปุ่ม "🎨 ธีม")
- โทนสี 7 แบบ (ปกติ/พาสเทล/ธรรมชาติ/พระอาทิตย์ตก/มหาสมุทร/ราตรี/โฟกัส) + โหมด ตามระบบ/สว่าง/มืด/ตามเวลา + ความหนาแน่น + ลดการเคลื่อนไหว
- ทำงานผ่าน CSS variables และ attribute บน <html> เท่านั้น ค่าปกติ = ไม่มี attribute จึงหน้าตาเดิมเหมือนเดิม; ผู้ใช้เลือกเองมีผลก่อน "ตามเวลา"
- ตรวจ contrast ของทุกโทนสีแล้ว (ตัวอักษรหลัก ≥ 7:1, ตัวอักษรรอง ≥ 4.5:1) ปุ่มสถานะยังกว้าง/สูง ≥ 44px ทุกความหนาแน่น
- รีเซ็ตธีมล้างเฉพาะ "weekly.theme.v1" ไม่แตะตาราง Checklist หรือเพลง; sync ข้ามแท็บผ่าน storage event

3) ปกเพลงที่ตั้งเอง (ไอคอน 🖼 ในแถวของรายการเพลง)
- เลือก JPG/PNG/WebP (≤ 15 MB) → ลากเลื่อน/ซูม/เลือก "เต็มกรอบ" หรือ "เห็นทั้งภาพ" → บันทึกเป็น JPEG 512×512
- ไม่เปลี่ยนโครงสร้าง IndexedDB (ยังเป็นเวอร์ชัน 1: tracks/blobs/covers จึงไม่ต้อง migrate) — เพิ่มฟิลด์ลง record เดิม:
  covers[id].custom / customAt และ tracks[id].hasCustomCover / thumbEmbedded; ข้อมูลเก่าที่ไม่มีฟิลด์เหล่านี้ทำงานเหมือนเดิม
- ลำดับแสดง: ปกที่ตั้งเอง > ปกที่ฝังในไฟล์ > ปกเริ่มต้น; ลบปกที่ตั้งเองแล้วกลับไปใช้ปกฝัง (ถ้ามี) ได้
- บันทึกปก + metadata ใน transaction เดียว ถ้าพื้นที่เต็มจะไม่เปลี่ยนอะไรและแจ้งเป็นภาษาไทย
- ลบเพลง → ปกถูกลบไปด้วย และตอนเปิดแอปมีการกวาดปกกำพร้า (ตรวจและลบใน transaction เดียว)
- แจ้งแท็บอื่นผ่าน BroadcastChannel; ปกอยู่ใน IndexedDB เท่านั้น (Service Worker ไม่แคช) ใช้งานออฟไลน์ได้ ไม่ส่งออกนอกเครื่อง

จุดที่แก้ของเดิม (เฉพาะจุดที่จำเป็น)
- index.html: getCover() อ่าน custom ก่อน blob; rowFor() เพิ่มปุ่มเปลี่ยนปก; handler คลิกรายการเพลง; เรียก sweepCovers() ตอนเปิด

- service-worker.js: cache v4 →
